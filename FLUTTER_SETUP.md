# Flutter migration setup

This branch contains the in-progress Flutter client. The Kotlin app on `main` is unchanged.

## Google / YouTube account sync

1. In Google Cloud Console, enable **YouTube Data API v3**.
2. Configure the OAuth consent screen and add the scope:
   `https://www.googleapis.com/auth/youtube.readonly`
3. Create an Android OAuth client for the application ID generated by the Flutter Android host, including your signing SHA-1 fingerprints.
4. Create a Web application OAuth client and provide its client ID at build time as:
   `--dart-define=GOOGLE_WEB_CLIENT_ID=YOUR_WEB_CLIENT_ID`
5. For CI, add a repository Actions secret named `GOOGLE_WEB_CLIENT_ID` and pass it as a dart-define in the workflow build command.

The app uses that OAuth grant to read the signed-in user's YouTube playlists and playlist items. On launch it asks the official Google Sign-In SDK to restore its cached session, so users should not need to sign in every time. This is the supported equivalent of a remembered login; it does not embed Google's login page or scrape browser cookies. It does not upload, edit, or delete YouTube playlists. Synced playlists are cached locally; local playlists remain device-only.

## Background playback

The Flutter client uses `just_audio_background` with media metadata. The CI workflow generates the Android host and adds the media service, media-button receiver, and foreground-service permissions before building. Android notification permission may still need to be granted on Android 13+.

## Current limitations

- YouTube/InnerTube and stream extraction libraries are unofficial and can break when upstream changes.
- Google sign-in requires the OAuth client setup above; no client ID or secret is committed.
- Verify the generated APK on a physical device, including notification controls, lock-screen controls, and playback after the app is backgrounded.
